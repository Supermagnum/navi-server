navi-server

CoMaps leaf MWM Navi sidecars for the Navi navigation app — wetland and boardwalk costing, elevation overrides, and vehicle height/width/length/weight limits — derived from OpenStreetMap extracts. This host is not a general map-tile or basemap server.

What you get

The public DocumentRoot serves MWM: zstd-compressed Navi sidecars and the catalog under /mwm/. Each leaf sidecar supplements the matching CoMaps .mwm with wetland Soft/Hard costs, elevation overrides, and optional vehicle_limits (VL01) for truck and height-restricted routing. Base map files come from CoMaps mirrors; this host publishes the matching Navi sidecars, catalog, region migration tables, and attribution.

Legacy .rkyv routing packs under /packs/ have been retired. They are no longer the supported download path and are not refreshed by the weekly bake. New clients should use CoMaps MWMs plus Navi sidecars via /mwm/. Migration notes: docs/client-migration-from-rkyv.md.

Format details live in the repo: docs/client-fetch-mwm.md (MWM catalog and fetch contract) and docs/sidecar-format.md (NVSC sections including vehicle_limits).

URL layout

Start at /mwm/current.json for the live CoMaps data-version pointer, then open that version’s catalog.json and download each leaf sidecar listed there (sha256 digests included). 

GET /mwm/current.json
GET /mwm/<version>/catalog.json
GET /mwm/<version>/<Leaf>.navi-sidecar.v1.zst
GET /mwm/<version>/attribution.json
GET /mwm/<version>/region-migration.json
GET /mwm/<version>/country_groups.json

Retired .rkyv URLs (/current.json, /packs/…) may still resolve on disk for historical clients; do not build new integrations against them.

How to fetch a region

  1. GET /mwm/current.json and note the active version.
  2. GET /mwm/<version>/catalog.json and pick leaf entries (skip any with no_sidecar: true).
  3. Download each sidecar_url; verify sidecar_sha256.
  4. Fetch the matching CoMaps .mwm from a CoMaps CDN using catalog size/sha1 fields; apply the sidecar only when the MWM fingerprint matches.

Clients use ordinary HTTP GET/HEAD only — no auth handshake and no upload API on this vhost. Full contract: docs/client-fetch-mwm.md in the navi-server repository.

Using the sidecars

These are Navi offline costing sidecars (NVSC v1, zstd), not map tiles. Other tools can fetch them over plain HTTP and load them with the same APIs Navi uses. Inspect with navi-mwm-sidecar inspect.

  1. Discover the active release via /mwm/current.json, then download files listed in catalog.json (verify sha256).
  2. Interpret section magic / versions (wetland, elevation, vehicle_limits): sidecar-format.md.

Update cadence

MWM sidecars track CoMaps map-data releases (for example 261105). Treat freshness as “last successful publish for that CoMaps version,” not real-time OSM. The former Monday 00:00 UTC .rkyv weekly bake is retired and no longer refreshes packs.

DATEX II traffic feeds

This host also caches DATEX II snapshots under /datex/ for Navi clients. The live registry is /datex/providers.json (credentials never listed). Canonical paths are /datex/<provider>/; legacy flat /datex/*.xml URLs redirect to NPRA.

Currently served (enabled with published data):

  • /datex/flanders/ — Flanders Verkeerscentrum (Belgium), DATEX v3
  • /datex/digitraffic/ — Digitraffic (Finland), DATEX II v2.3
  • /datex/tipi/ — TIPI / Bison Futé DIR (France), DATEX II v2
  • /datex/cita/ — CITA (Luxembourg), DATEX II v2
  • /datex/ndw/ — NDW (Netherlands), DATEX v3
  • /datex/bulgaria/ — Bulgaria RIA (LIMA Datasheet), DATEX II v2
  • /datex/mobie/ — MOBI.E EV charging (Portugal NAP), DATEX v3.3
  • /datex/npra/ — NPRA / Statens vegvesen (Norway), DATEX II v3.1 (server-side Basic auth)

Open no-registration sources and operator notes: docs/datex-open-feeds.md. NPRA plugin: docs/datex-npra.md. Multi-provider setup: docs/datex-providers.md.
