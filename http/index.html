navi-server

Pre-built routing packs for the Navi navigation app — graph, POI, wetland/hazard, and elevation-aware costing — derived from OpenStreetMap extracts. This host is not a general map-tile or basemap server.

What you get

Each published region is a set of binary packs plus JSON manifests that Navi can download and use for offline routing. Content includes routing geometry (profiles such as car / truck / foot / bicycle), named POIs and barrier data, and wetland/hazard rings used in costing — not a Protomaps-style labeled-region or park-boundary basemap layer.

Format details live in the repo: docs/pack-formats.md (graph / POI-barrier / wetland archives and magic bytes).

URL layout

Packs are nested under Geofabrik download paths — the same continent/country/region hierarchy the Navi app uses in its download menu (for example europe/norway/vestlandet or north-america/us/west-virginia). 

GET /current.json
GET /packs/<geofabrik-path>/<generation>/manifest.json
GET /packs/<geofabrik-path>/<generation>/<stem>.navi-manifest.json
GET /packs/<geofabrik-path>/<generation>/<stem>.navi-graph-*.rkyv
GET /packs/<geofabrik-path>/<generation>/<stem>.navi-poi-barrier.rkyv
GET /packs/<geofabrik-path>/<generation>/<stem>.navi-wetland*.rkyv

Start at /current.json for the live catalog (generation id and per-region manifest_url). Then fetch that region’s manifest.json and the files it lists (sha256 digests included). The convert-style <stem>-latest.navi-manifest.json sits beside those packs in the same generation folder.

How to fetch a region

  1. GET /current.json and pick a region entry.
  2. GET its manifest_url (under /packs/…/).
  3. Download each file named in the manifest; verify sha256.

Clients use ordinary HTTP GET/HEAD only — no auth handshake and no upload API on this vhost. Full contract: docs/client-fetch.md in the navi-server repository.

Using the binary packs

These are Navi offline routing packs (rkyv archives + JSON manifests), not map tiles. Other tools can fetch them over plain HTTP and load them with the same APIs Navi uses.

  1. Discover regions via /current.json, then download files listed in each region’s manifest.json (verify sha256). Contract: client-fetch.md.
  2. Interpret magic bytes / versions and deserialize graph, POI-barrier, and wetland packs: pack-formats.md — especially How to read them (load_graph_pack, load_poi_barrier_pack, load_wetland_pack in pack_convert_core::routing::indexed).

There is no Python decoder for pack bodies; supported load path is Rust (rkyv 0.8) as documented above.

Update cadence

Binary routing packs are refreshed every Monday at 00:00 UTC by the weekly bake timer. Treat freshness as “last successful Monday bake,” not real-time OSM. Wider planet leaf builds are occasional full-tree runs, separate from that weekly cadence.

Optional DATEX (Norway)

This host may also cache NPRA DATEX II snapshots under /datex/ for Navi clients. That feature is off by default, separate from routing packs, and holds credentials only on the server. See docs/datex-npra.md in the repository.

Other European DATEX II feeds that need no registration (France TIPI open DIR events, Flanders, Finland Digitraffic, Luxembourg CITA, Dutch NDW open data, and similar) are catalogued in docs/datex-open-feeds.md, cross-checked against graphhopper/open-traffic-collection (portals that still need signup are marked there). They are not polled by navi-server today. To wire another provider, see docs/datex-adding-sources.md.
